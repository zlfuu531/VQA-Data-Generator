# 多轮对话历史保存说明

## 当前保存逻辑

### 保存到 `conversation_history` 的模型回答

**代码位置**：`evaluator.py` 第342-345行

```python
brief_answer_for_history = extracted_answer if extracted_answer and extracted_answer.strip() else (
    original_response[-500:] if len(original_response) > 500 else original_response
)
```

### 保存策略

1. **优先使用 `extracted_answer`**（如果成功提取到）
   - 来源：从 `model_answer` 中提取的答案（通常是从 `\boxed{}` 中提取）
   - 内容：**只包含最终答案，不包含思考过程**
   - 示例：`"A"` 或 `"这是答案"`

2. **如果没有提取到，使用 `original_response`**
   - 来源：原始的 `model_answer`（完整响应）
   - 内容：**包含完整的思考过程和答案**
   - 限制：如果超过500字符，只保存最后500字符

### 数据流向

```
call_model_api() 
  → model_answer (完整响应，可能包含思考过程)
    → extract_answer_from_response()
      → extracted_answer (提取的答案，不包含思考过程)
      → original_response (= model_answer，包含思考过程)
        → brief_answer_for_history (保存到历史中的内容)
```

## 对于包含思考内容的模型

### 问题

如果模型返回的内容包含思考过程（thinking/reasoning），例如：
```
让我仔细分析这个问题...

首先，我需要考虑...
经过分析，我认为...

\boxed{A}
```

当前逻辑：
- ✅ 提取到了 `extracted_answer = "A"`
- ✅ 保存到历史的是 `"A"`（**思考过程丢失**）

### 影响

- **优点**：节省token（只保存最终答案）
- **缺点**：下一轮对话时，模型看不到之前的推理过程，可能影响多轮对话的连贯性

### 可选方案

如果需要保留思考过程，可以修改为：

```python
# 方案1：总是保存完整响应（包含思考过程）
brief_answer_for_history = original_response[-500:] if len(original_response) > 500 else original_response

# 方案2：保存完整响应，但限制长度
max_history_length = 1000  # 可以根据需要调整
brief_answer_for_history = original_response[-max_history_length:] if len(original_response) > max_history_length else original_response

# 方案3：优先保存完整响应，但如果没有则使用提取的答案（与当前逻辑相反）
brief_answer_for_history = original_response[-500:] if len(original_response) > 500 else original_response if original_response else extracted_answer
```

## 建议

- 如果模型的思考过程对多轮对话很重要，建议使用方案1或方案2（保存完整响应）
- 如果只需要最终答案，当前逻辑已足够（节省token）
- 可以根据模型类型选择不同的策略（例如：对于thinking模型使用完整响应，对于普通模型使用提取的答案）
