# 多轮问题答案丢失问题分析

## 问题现象

1. 所有154个多轮问题的答案都是空的（`answer`和`process`都是空字典）
2. `response_time`都是0，说明模型API调用可能失败或返回空响应
3. 但是`match_gt`有值（都是False），说明至少进行了评判
4. 统计信息显示多轮问答题的`total_count`为0（因为答案都是空的，统计代码只统计有非空答案的题目）

## 问题定位

### 1. 数据流分析

从代码流程看：
- `evaluator.py`第297行：调用`call_model_api`获取`model_answer`
- 第306行：调用`extract_answer_from_response`提取`extracted_answer`
- 第424行：保存`model_answer`作为`process`，`extracted_answer`作为`answer`
- 第440行：保存到`rounds_data[round_key][model_name]`

### 2. 可能的原因

**原因1：模型API调用失败但异常被捕获**
- 如果模型API调用失败，会进入异常处理（第442-456行）
- 异常处理会设置`model_answer=""`和`extracted_answer=""`
- 但是实际数据中没有`error`字段，说明可能不是异常处理的问题

**原因2：模型返回了空响应**
- 如果`call_model_api`返回空字符串，`extract_answer_from_response`也会返回空
- 但是`response_time=0`，说明可能根本没有调用API，或者调用立即返回了

**原因3：答案提取逻辑有问题**
- 从日志看，模型确实有返回内容（一个很长的回答）
- 但最终保存的答案和process都是空的
- 这说明问题可能出在答案提取或保存阶段

## 修复建议

logging.info(f"    轮次{round_num} 模型{model_name} API调用结果: response_time={response_time}, answer长度={len(model_answer) if model_answer else 0}")
```

```

## 临时解决方案

如果需要快速修复，可以在`result_converter.py`中修改逻辑，当`extracted_answer`为空时，尝试从`model_answer`获取：

```python
# 如果 extracted_answer 为空，尝试从其他字段获取
if not round_answer:
    round_answer = round_data.get("answer", "")
    # 如果还是为空，尝试从model_answer提取（作为保底）
    if not round_answer:
        model_answer = round_data.get("model_answer", "")
        if model_answer:
            # 尝试从model_answer中提取答案
            from .model_api import extract_answer_from_response
            round_answer, _, _ = extract_answer_from_response(model_answer, False)
```
